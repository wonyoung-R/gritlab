### 0-G. 배포 후 회귀 발견 + 재수정 (2026-08-24)

사장이 실제 배포본에서 #1·#2·#7 재현 안 됨을 보고 → 브라우저 캐시 문제로 오판했으나, 로컬 dev + Playwright 실브라우저 테스트로 재현한 결과 **#1이 진짜 버그였음을 확인**.

**버그 1 — `word-break: keep-all`이 CJK 줄바꿈 규칙과 반대로 작동**: 한글은 기본적으로 음절 사이 어디서든 줄바꿈 가능한데 `keep-all`은 그 CJK 줄바꿈을 억제하는 속성 — 공백 없는 긴 한글 이름이 줄바꿈을 전혀 못 하고 그대로 잘림. `word-break: normal`로 교체(사실상 기존 declare 제거)해 해결. 실브라우저 스크린샷으로 재현→수정→검증 완료.

**버그 2 (수정 과정에서 신규 발견) — `.teamBlock::before`의 `transition: border-color 0.4s, background 0.4s`가 렌더링 버그 유발**: 팀명이 줄바꿈되며 박스 높이가 바뀌는 순간 이 트랜지션 때문에 브라우저가 절대위치 테두리 가상요소(`::before`, `inset:4px`로 테두리를 그리는 기존 기법)를 일부만 그리는 현상 발생(사장이 스크린샷으로 제보: "오른쪽 파란 테두리 왼쪽이 사라짐"). `#7 좌우반전`과는 무관 — 순수하게 "박스 높이가 바뀌는 이벤트" 자체가 트리거였음(좌우반전 없이 이름만 길게 해도 재현됨, DOM 삽입 순서·`elementFromPoint`·`::before` transition 개별 무력화 테스트로 원인 격리). **기존에 있던 코드**이고 이번에 새로 만든 게 아님 — 지금까지는 이름이 항상 한 줄로 잘려 박스 높이가 안 바뀌었기 때문에 드러나지 않았던 잠재 버그. `transition` 선언 제거로 해결.

**검증 방법**: 로컬 dev 서버(`npm run dev`) + Playwright로 실제 브라우저에서 재현 → 수정 → 재현 스크린샷으로 확인(#1, #6, #7 모두 시각 확인 완료). #2는 로그인 필요한 Admin 화면이라 소스+배포 번들 문자열 검사로만 확인(직접 조작 테스트 못 함). #5(부저)는 오디오라 스크린샷 검증 불가.

**교훈**: `npm run build` 통과 ≠ 실제 브라우저에서 의도대로 렌더링됨. 이번 세션부터 UI 변경은 로컬 dev + Playwright 실브라우저 확인을 기본 절차로 한다.

### 0-H. 추가 발견 — 헤더 "GRIT LAB" 로고 화면 밖 넘침 (2026-08-24, 원래 7건과 무관한 기존 버그)

사장이 헤더 스크린샷 제보: "GRIT LAB" 타이틀과 농구공이 크림색 헤더 바 위아래로 삐져나옴.

**원인**: `Scoreboard.jsx:537` 타이틀 텍스트가 `fontSize: 84`(고정 px) 하드코딩. 이 텍스트를 담는 `.periodBadge`는 `position: absolute`라 `.header`의 실제 높이 계산에 전혀 기여하지 않음. `.header`의 실제 높이는 옆의 작은 아이콘 버튼들(약 40px)+패딩으로 결정되는데, 그게 84px보다 작아서 절대위치인 타이틀이 헤더 바 밖으로 삐져나옴. 이번 세션 변경과 무관한 기존 버그 — Admin.jsx는 이미 실제 로고 이미지(`10vh` 반응형)로 교체돼 있어 이 문제가 없었음.

**수정 (사장 요청 — "유동적으로")**: 고정 min-height 패치 대신, CSS 변수 `--title-size: min(8vh, 84px)`로 타이틀 폰트 크기와 헤더 `min-height`(`calc(var(--title-size) + 48px)`)를 하나로 묶음 — 화면 크기가 어떻게 바뀌든 헤더가 항상 타이틀보다 넉넉하게 크도록 구조적으로 보장. Playwright로 일반 화면(900px 높이)과 극단적으로 낮은 화면(500px 높이) 둘 다 검증 — 후자에서 타이틀이 비례해서 축소되며 넘침 없음 확인.

파일: `Scoreboard.jsx`, `scoreboard.module.css`

- **별도 예외처리 불필요한 이유**: `standingRowsFor`(순위 계산)는 `round?.startsWith('GROUP_')`만, `maybeAutoFillBracket`(4강 자동시딩)는 `GROUP_*`/`SEMI`만 필터링 — `'EXTRA'`는 둘 중 어디에도 안 걸려 자동으로 제외됨. `ROUNDS` 탭 배열에도 안 넣어서 라운드탭에 안 뜸(의도된 것 — 즉석 1회성 경기라 브라우징 UI 불필요)
- 라이브 화면 라운드 라벨: `liveMatch.round === 'EXTRA'` → "추가경기"로 별도 표시
- UI: 대시보드 "경기 관리" 섹션에 버튼 추가 + 팀명 입력 모달(취소/3분 경기 시작)

**미검증**: Admin.jsx는 로그인 필요 화면이라 Playwright로 실제 클릭 흐름 테스트 못 함 — 소스 리뷰로 로직 검증(다른 라운드 필터링 로직 전수 확인해 EXTRA가 어디에도 안 걸리는 것 확인). **사장 로그인 후 실제 확인 필요**: 버튼 클릭 → 팀명 입력 → 3분 경기 시작 → 종료·저장 → 순위표에 안 뜨는지.

### 0-R. 페이지 구조 혼선 정리 + "대회 삭제" 무반응 버그 발견·수정 (2026-08-27)

**사장이 "추가경기 만들기"를 못 찾는다고 함 → 조사 결과 페이지 구조 자체를 다시 정리할 필요가 있었음.**

실제 동선: 로그인 → 모드 선택(`/threevthree/admin`) → **"관리자모드" 클릭 시 `tournament.html`로 완전히 이동**(다른 정적 페이지, React 앱 아님) → 거기서 특정 대회의 "🔴 라이브 전광판" 클릭 → `/tournament/manage-3v3/{id}?manage=1`로 이동해야 비로소 `Admin.jsx`(내가 0-Q에서 버튼 넣은 화면)가 `activeTournamentId`까지 세팅된 채로 뜸. 즉 "추가경기 만들기"는 `tournament.html`이 아니라 그 다음 화면에 있음 — 사장은 `tournament.html`에서 찾고 있었던 것.

**"대회 삭제 눌러도 반응 없음" — 사장이 재현·제보, 조사해서 진짜 버그로 확인**:
`tournament.html`의 `onclick="deleteTournament('${t.id}')"`가 항상 **문자열**을 넘기는데, `TOURNAMENTS` 배열의 `t.id`는 Supabase에서 온 **숫자**. `TOURNAMENTS.find(x => x.id === id)`가 `숫자 === 문자열`로 항상 `false` → `t`가 `undefined` → `if(!t) return;`으로 **아무 알림도 없이 조용히 종료**. "1초 뒤 새로고침" 땜빵 대신 근본 원인(타입 불일치)을 고침 — `String(x.id) === String(id)`로 비교 통일 + `t`를 못 찾으면 이제 alert로 알림(무음 실패 금지).

**파급 점검(STANDARDS M4)**: 같은 `onclick="fn('${t.id}')"` 따옴표-문자열 패턴을 쓰는 다른 함수도 검색 → **`toggleTournamentStatus`(대회 진행중/종료 전환)와 `resumeInBuilder`(빌더에서 이어하기)도 동일 버그**로 확인, 같이 수정. (`selectTournament`/`renameTeam` 등은 함수 참조 또는 따옴표 없는 숫자 리터럴로 호출돼 있어 문제 없음 — 확인함.)

### 0-S. "대회 삭제" 재제보 — 진짜 원인은 따로 있었음 (0-R 수정으로 해결 안 됨, 2026-08-27)

**사장 재현 결과**: "추가경기 만들기"는 확인됨. "대회 삭제"는 여전히 안 됨 — 단 증상이 바뀜: **1단계 확인창(confirm)은 정상 표시**되고 OK를 눌러도, **2단계 대회명 입력창부터 안 뜸**. 스크린샷 확인 결과 이 대화상자는 브라우저 기본 UI가 아니라 **앱 아이콘이 박힌 네이티브 macOS 스타일 창** — 즉 사장이 이 페이지를 **PWA(독립 설치된 웹앱)로 실행 중**이라는 뜻.

**진짜 근본원인**: `window.prompt()`. 설치형 PWA 창은 `confirm()`/`alert()`는 지원하지만 텍스트 입력이 필요한 `prompt()`는 조용히 무시(즉시 종료, 대화상자 자체가 안 뜸)하는 경우가 있음 — 0-R에서 고친 문자열/숫자 타입 불일치와는 **완전히 별개의 버그**였음. 0-R 수정은 그 자체로 맞는 수정이었으나 이 문제는 해결하지 못했던 것.

**수정**: `window.prompt()` 의존 제거, 페이지 내장 커스텀 모달(`#cpModal` + `customPrompt()` 함수, Promise 기반)로 교체. 기존 다크테마 `.field`/`.btn` 클래스 재사용해 스타일 일치. `confirm()`은 정상 동작 확인됐으므로 그대로 유지(최소 diff 원칙).

**파급 점검(M4)**: `grep`으로 `prompt(` 전체 검색 → 이 1곳이 유일한 사용처, 추가 수정 불필요. 부수적으로 같은 파일 내 키보드 안내 모달(`kbdImgModal`)에 방향키(±1초)·R(리셋) 안내 문구가 **정적 텍스트로 남아있는 것 발견** — 실제 키 핸들러는 아니라 동작엔 무관하지만 #2/#3 요구사항과 내용이 어긋나 같이 삭제.

검증: `node --check` 통과. 실제 클릭 동작(PWA 창에서 새 모달 정상 표시)은 사장 로컬 재테스트 필요 — **아직 커밋 전, 사장 확인 후 커밋 진행** ("로컬에서 확인해보고 그다음에 커밋 진행하자" 지시 준수).

  - Given 예선 미완료 경기 존재, When "4강 생성" 클릭, Then "예선 미완료 경기 N건" 경고 후 차단된다
  - Given 조 내 동률(같은 승수), When 집계, Then 득실차 → 다득점 순으로 순위를 결정한다
- **관련 화면**: Admin 관리 화면

### FR-03: 대진표 드래그 앤 드롭 수정 — **Should**
- **설명**: 생성된 대진표에서 팀을 드래그하여 다른 경기 슬롯과 교환한다.
- **인수 기준**:
  - Given PENDING 상태 경기 2개, When 팀 A를 다른 경기 슬롯으로 드래그, Then 두 팀 위치가 교환되고 DB에 즉시 반영된다
  - Given LIVE/ENDED 경기, When 드래그 시도, Then 이동이 차단되고 "진행/종료된 경기는 수정 불가" 안내가 표시된다
- **관련 화면**: Admin 대진표 섹션

### FR-04: 샷클락 표시 버그 수정 — **Must**
- **설명**: 샷클락 12초 리셋 시 "12"가 1초간 표시된 후 11로 전환되도록 수정. 동시에 "5" 표시 누락도 해결.
- **인수 기준**:
  - Given 샷클락 12초 리셋, When 카운트 시작, Then "12"가 1.0초간 표시된 후 "11"로 전환된다
  - Given 카운트다운 진행, When 6→5초 구간 진입, Then "5.0"부터 0.1초 단위 표시로 자연스럽게 전환된다 (5 누락 없음)
  - Given 바탕화면(`/threevthree`)과 Admin 라이브 둘 다, Then 동일하게 동작한다
- **관련 화면**: Scoreboard.jsx + Admin.jsx 라이브 전광판

### FR-05: 경기 종료 후 대기 화면 — **Must**
- **설명**: 경기 종료(저장) 후 "다음 경기 시작까지 남은 시간" 카운트다운 화면을 표시한다.
- **인수 기준**:
  - Given 라이브 경기에서 "저장 & 종료" 클릭, When 저장 완료, Then 전체 화면 카운트다운(기본 1:30)이 표시된다
  - Given 카운트다운 화면, When 1:00 / 1:30 선택 버튼 클릭, Then 해당 시간으로 재설정된다
  - Given 카운트다운 0 도달, When 종료, Then 부저가 울리고 Admin 관리 화면으로 복귀한다
  - Given 카운트다운 중, When "건너뛰기" 클릭, Then 즉시 관리 화면으로 복귀한다
- **관련 화면**: Admin (라이브 종료 직후)

### FR-06: 키보드 조작 — **Must** ✅ 완료
