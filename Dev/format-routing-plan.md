### 1-C. 도출한 규칙 (사장 표 6행 전부 재현됨)

```
R1. 조 크기는 3 또는 4만. (2팀 조·5팀 조 없음)
R2. 플레이오프 = 조 1위 전원이 들어가는 가장 작은 브라켓:  조 ≤ 4 → 4강  /  조 ≥ 5 → 8강
R3. 조 수 = floor(N/3) — 3팀 조를 최대한 쓰고, 나머지 인원만 4팀 조로 흡수(뒤쪽 조에 배치)
    ※ 2026-09-03 사장 지시로 12팀을 4/4/4(3조·WC 1) → 3/3/3/3(4조·WC 0)으로 변경.
      그 결과 ceil/floor 두 갈래였던 규칙이 floor(N/3) 하나로 단순해졌고, 사장 확정 6행이 전부 그대로 재현된다.
      13·14팀 경계(D1)도 자동으로 4조 → 4강 · 와일드카드 없음으로 결정됨 → D1 해소.
R4. 진출 = 조 1위 전원 + 와일드카드(플옵 인원 − 조 수)
R5. 와일드카드 우선순위 (사장 10팀 행에서 일반화 — D2 확인 필요):
    ① 조 크기가 다르면 큰 조(4팀) 2위가 먼저 (10팀: 4팀조 2위 자동)
    ② 같은 크기끼리는 득실차 → 다득점 → 최소실점 → 완전동률 시 추첨(기존 로직)
    ③ 슬롯 ≥ 후보 수면 비교 없이 전원 진출 (13·14팀: 2위 전원)
R6. 조 1위 동률(승수 같음) 처리 — 동률 팀 수로 갈린다.
    ※ 결정전(3분 단판)이 발생하는 조건 = **4팀 조에서 2승 팀이 2팀** (사장 2026-09-03 명시).
      3팀 조는 팀당 2경기라 승수가 (2,1,0) 아니면 (1,1,1)뿐 → 2승 2팀이 구조적으로 불가능.
      따라서 결정전은 4팀 조가 있는 대회에서만 발생: 7·8·10·11·13·14·16·17팀
      사장 확정(2026-09-03): 이 여덟 구성 전부 적용:
    · 2팀 동률 → 추가경기(3분)로 확정. 그 전까지 자동 시딩 보류 (§1-E 위험 #1)
    · 3팀 이상 → 맞대결이 순환이라 추가경기 1경기로 못 가림. 득실차 → 다득점으로 정렬해 진행하고 근거를 화면에 표시.
      단 득실차·다득점까지 완전히 같으면 정할 근거가 없으므로 보류(추첨 대상).
    ※ 3팀 조는 팀당 2경기라 승수 분포가 (2,1,0) 또는 (1,1,1)뿐 — 2팀 동률이 구조적으로 불가능하고 동률은 항상 3파전이다.
      12·15·18팀처럼 전 조가 3팀인 대회에서는 3파전 경로만 발생하며, 순환 확률이 조당 25%라 자주 나온다.
      이 때문에 3파전을 무조건 보류하면 대회가 자주 멈춰 득실차 정렬로 진행하도록 정했다.
R7. 본선 시딩 (사장 추가 요청 2026-09-03): 진출팀을 성적순으로 1~4위(8강은 1~8위) 세운 뒤
    4강 = 1 vs 4 / 2 vs 3,  8강 = 1v8 / 2v7 / 3v6 / 4v5 → 승자끼리 (1v8 승자 vs 4v5 승자) / (2v7 승자 vs 3v6 승자)
    순위 기준(D7 확인): ① 조 1위 전원이 와일드카드보다 위 ② 같은 그룹 안에서는 승률 → 경기당 득실차 → 경기당 득점
       (3팀조 2경기·4팀조 3경기라 경기 수가 달라 총계가 아닌 경기당 값으로 비교) ③ 완전동률 추첨
    같은 조 회피(R7-b): 1v4가 같은 조면 4시드↔3시드 교환. 8강은 조당 최대 2팀이라 회피 배치가 항상 존재 → 탐색으로 보장
R8. 3·4위전 없음 (사장 확정 2026-09-03). 본선 경기 수 = 4강 3경기(2+1) · 8강 7경기(4+2+1).
    코드상 `3RD_PLACE` 라운드 id는 남아있으나 빌더·Admin 어디서도 자동 생성하지 않음(레거시 대회 호환용으로만 유지).
R9~R10. (2026-09-03 사장 정정) **모든 팀 예선 2경기 보장.** 4팀 조는 풀리그(팀당 3경기)가 아니라
    부분 리그로 4경기(팀당 2경기) 편성한다 — 빌더의 `팀당 경기 수 = 2` 설정에 해당(`groupScheduleEx`가 이미 지원).
    결과: 조별 경기 수 = 조 인원, **예선 총 경기 수 = 접수팀 수**. 총 경기 = 접수팀 수 + 3(4강) 또는 + 7(8강).
    ※ 이 정정 전에는 4팀 조를 풀리그로 잡아 경기 수를 과다 계상했었다(12팀 21경기 → 실제 15경기).
    ※ R5-①(큰 조 2위 우선)의 근거도 "경기를 더 치렀다" → "4팀 중 2위가 3팀 중 2위보다 어렵다"로 바뀐다.
      팀당 경기 수는 이제 모두 같기 때문. 순위 비교의 경기당 환산은 과거 풀리그 대회·몰수 대비로 유지.
```

### 1-J. 2차 구현 내역 (2026-09-03) — 8강 + 빌더 자동 편성

**부저 지연(#5) 원인 규명 — 이미 해소돼 있었음**
음원은 정상(선행 무음 10ms 이하). 진짜 원인은 **화면과 소리의 1초 어긋남**이었다.
`Math.floor` 표시에서는 실제 시간이 1.0초 남았을 때 이미 "00:00"이 떠서, 부저가 1초 늦게 우는 것처럼 보였다.
0-U(2026-08-27)의 `Math.ceil` 전환으로 표시와 부저가 같은 시점이 되어 이미 해결된 상태다. 시뮬레이션으로 확인(floor 1.00초 어긋남 → ceil 0.00초).
부수적으로 **부저를 React 상태 업데이터 밖으로 분리**했다. 업데이터 안에서 소리를 내면 React가 렌더를 스케줄한 뒤 실행되고, StrictMode·동시성 모드에서는 두 번 울릴 수 있다. 최신 클락 스냅샷(ref)으로 판정해 즉시 울리고, 중복 발사 가드를 뒀다. 매 틱 `wakeCtx()`로 오디오 컨텍스트도 깨워둔다(Admin·Scoreboard 양쪽).

**8강 자동 편성 (Admin)**
- `maybeAutoFillBracket` 재작성: 예선 종료 → 조 수로 4강/8강 판정(R2) → 본선 1라운드 시딩 → 8강 종료 시 4강 편성 → 4강 종료 시 결승. 라운드 쓰기를 `writeBracketRound`로 공통화.
- `advancePairs` 추가 — 8강 승자 교차 배치(1v8 승자 vs 4v5 승자 / 2v7 vs 3v6).
- `ROUNDS`에 예선 C~F 추가(18팀 = 6개 조까지). 실제 경기가 있는 라운드만 화면에 나온다.
- `downstreamSeeded`가 8강 경유 체인(예선 → 8강 → 4강 → 결승)을 반영.

**빌더 자동 조편성 (tournament.html)**
- 참가 팀 수를 입력하면 조 수·팀당 경기 수가 표준값으로 자동 설정. 직접 고치면 미리보기에 "표준과 다름" 배지.
- 미리보기가 4강/8강·와일드카드 자리·본선 경기 수를 표시. 기존 "5조↑ 별도 규칙 필요" 경고 제거.
